## Measured performance corrections

- Escaping a 64 KiB ASCII preview fell from 65,550 allocation calls to one.
- Formatting seven rows with eight retained 64 KiB cells each fell from
  7,707,319 to 397,975 cumulative allocated bytes (94.8% less).
- Raw inspection of 2,000 JSON objects fell from 18,378 allocation calls to 355
  by skipping an unused parsed tree.
- A result with a 70,000-byte retained value and a rejected 1 MiB final value
  now reserves 70,000 spool bytes instead of 1,118,576; both adapters skip
  converting and writing fields from rows beyond the cap.
- Byte-cap rejection now releases a discarded 8 MiB capture while preserving
  the earlier 70,000-byte value and its references. It still performs the
  initial write; the improvement is retained disk/quota reclamation.

These are deterministic allocator and storage measurements, not RSS or
end-to-end latency claims. Existing text, Unicode, control escaping, truncation and row identities
remain covered by regression tests.
